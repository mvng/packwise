## 2024-05-21 - N+1 Query Fix with Payload Deduplication in syncDayPlans
**Learning:** When flattening nested Prisma \`create\`/\`update\` calls into a single \`$transaction\` array to fix an N+1 issue, if the payload can contain duplicates (e.g., syncing multiple day plan items to the same packing list), you must deduplicate the payload *before* queuing the operations. Otherwise, the code might queue a \`create\` with a temporary ID and then immediately try to queue an \`update\` using that temporary ID, which causes the transaction to crash with a \`RecordNotFound\` error.
**Action:** Always inspect the potential for intra-payload duplicates before generating a batch of Prisma operations. Deduplicate items in memory (e.g., using a Map) before looping to generate the \`create\` and \`update\` promises.
