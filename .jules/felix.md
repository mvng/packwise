## 2026-03-11 - Trip sharing post-login fork workflow redirect
**Learning:** Found an issue where the auth success handler in `app/(auth)/login/page.tsx` unconditionally redirected to `/dashboard` even if a `fork_trip_after_login` flag existed in `sessionStorage`. This prevented the post-login fork workflow from completing successfully, requiring the user to navigate back to the shared trip to fork it.
**Action:** Always intercept successful login/signup events on the client side when there's an intended post-login action stored in `sessionStorage` or `localStorage`. Clear the storage item immediately after successful execution to prevent repeated unintended actions, and use `window.location.href` for full page reload redirects to ensure server-side auth state is properly synchronized.
