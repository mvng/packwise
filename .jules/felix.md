## 2026-06-25 - Fixing auth flow state loss in Next.js
**Learning:** Next.js auth callback transitions (specifically redirecting from an auth callback back to a protected client page like `/dashboard` after a sign in/up) aggressively reset or obscure stored browser state if not carefully intercepted on the client. `handleAuth` needs to explicitly check `sessionStorage` for redirect/action intents *before* calling `window.location.href = '/dashboard'`, otherwise side-effect flows (like forking a trip after forcing a user to login) will be silently dropped.
**Action:** When implementing post-login flows that require executing a server action and then navigating elsewhere, always intercept the successful auth response on the client, check `sessionStorage` for the stored intent, execute the necessary action, clear the storage, and dynamically override the `window.location.href` to bypass the default dashboard redirect.
